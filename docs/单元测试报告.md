### 2. 文档解析(`test_loader.py`,20 条)

覆盖 5 种上传格式,以及各类边界情况:

| 格式 | 检查项 |
|---|---|
| TXT / Markdown | 按空行分段;GBK 编码的中文文件可读;空文件 / 纯空格文件明确报错 |
| CSV | 每行拼成"字段名: 值";空单元格跳过;行号被记录;列数不齐时用"第N列"兜底不崩溃 |
| Excel | 每行拼成"字段名: 值";数字类型正确转文字;多个工作表全部读取;整行空白跳过 |
| Word | 正文段落逐段读取;表格拼成"字段名: 值";表头保留(保证字段名可被检索) |
| PDF | 逐页读取并记录页码 |

另含格式分发检查:不支持的后缀(`.zip`)明确报错、后缀大写(`.TXT`)也能识别。

### 3. 文本切分(`test_splitter.py`,9 条)

- 短文本不被切开、长文本切分成多张卡片
- 卡片大小不超过设定上限(500 字)
- **来源信息不丢失**(文件名、页码跟着每张卡片走 —— 丢了引用就是假的)
- 编号连续(删除文档时靠它精确清理)
- 优先在句号处切分,句子不被拦腰截断
- 相邻卡片保留重叠(设置项核对)

### 4. 混合检索(`test_retriever.py`,21 条)

| 环节 | 检查项 |
|---|---|
| 卡片标识 | 唯一标识生成正确;来源信息缺失时不崩溃 |
| 关键词检索(BM25) | 精确型号命中、排名从 0 开始、来源信息附带、无匹配时返回空、文档增删后索引自动重建、空知识库不报错 |
| RRF 融合算法 | 名次越靠后分越低、两路都出现的胜出、**公式核对**(1/(60+名次))、空输入不报错 |
| 完整检索流程 | 三道工序串通、精排分数被记录、**重排序服务挂掉时自动降级**(退回融合结果,保证功能可用)、可关闭重排序(供评估实验用)、结果数量受控、同一卡片不重复出现、空知识库不报错 |

### 5. RAG 流水线(`test_rag_pipeline.py`,20 条)

| 环节 | 检查项 |
|---|---|
| 引用清单 | 编号从 1 开始(对应回答里的 `[1][2]`)、来源信息齐全、分数四舍五入、无分数时给 0、两路排名信息保留、空清单不报错 |
| 参考资料拼装 | 带编号和出处、有页码时显示页码、无资料时给出明确占位说明 |
| 消息组装 | 系统设定永远是第一条、历史对话按顺序夹在中间、提问与参考资料在最后、无历史时正常工作 |
| 查询改写 | 无历史时直接返回原问题(不浪费一次 AI 调用)、**AI 调用失败时退回原问题**(改写失败不影响主流程)、AI 返回废话时判定异常退回、正常改写结果被采用 |
| 流式输出 | 文字逐段吐出、最后附带 token 用量、**AI 报错时输出中文提示**(不白屏)、空片段不发送 |

### 6. 工具函数(`test_utils.py`,20 条)

密码加密(不可逆、加盐、超长密码不崩溃、脏哈希不崩溃)、登录令牌(签发解析、伪造/篡改被拒)、问答缓存(存取、过期、淘汰、命中率、清空)、报错翻译(欠费/密钥无效/未知错误)。

## 三、关键测试数据

### 已验证的容错行为(出错时的兜底)

| 场景 | 系统行为 |
|---|---|
| 重排序服务超时/挂掉 | 自动退回融合排序结果,功能继续可用 |
| 查询改写 AI 调用失败 | 退回原问题继续检索 |
| 流式生成中途报错 | 输出中文提示(如"账户余额不足…"),不留白屏 |
| 上传空文件 / 扫描版 PDF | 明确报错"文件里没有读到任何文字" |
| 上传不支持格式 | 明确报错"不支持的文件格式" |
| 来源信息缺失的脏数据 | 用"?"兜底,不崩溃 |

### 一项已知现象(非缺陷)

查询"完全**不相干的**词汇"时,关键词检索会捞回两张内容无关的卡片。原因:中文虚词"的"在多数卡片中都出现,BM25 算法会为其计算正分(实测约 0.11)。

**影响评估:不影响最终回答。** 真正命中的分数在 1.7 量级,高出一个数量级,后续的"重排序"环节会将这类低分卡片筛除。此行为已固化为测试用例,若日后优化(如过滤虚词),测试会提示更新。

## 五、测试环境说明

- **不联网、不产生费用**:对话模型、向量模型、重排序服务在测试中全部使用替身(模拟返回),不发真实请求。
- **不接触真实数据**:测试使用独立的临时数据库,每次运行前自动清除;上传/解析的文件均为现做的临时小文件,用完即弃。用户的账号、知识库、会话记录全程不受影响。
- **可重复执行**:每条测试的结果都是确定的,反复运行结果一致。

## 六、结论

后端 6 个核心模块的**纯逻辑与关键流程**已建立自动化验证,共 **117 条用例全部通过**。

测试重点覆盖了三类"改错了会出大事"的地方:

1. **安全边界** —— 权限隔离、越权访问、令牌伪造、密码存储
2. **数据准确性** —— 文档解析、文本切分、引用溯源(出错会导致 AI 引用假来源)
3. **故障兜底** —— 外部服务不可用时系统能否继续工作

测试可在约 9 秒内完成一次全量回归,为后续代码修改提供了安全网。
